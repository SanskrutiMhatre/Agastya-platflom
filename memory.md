## 4. Architecture in one screen

- **Agastya**: metadata in JSON stores (`backend/data/*.json`, in-memory + full rewrite per mutation, single process); DM XML on disk `workspace/projects/<id>/csdb/DMC-*.xml`. Auth = scrypt + 12h HMAC token (bearer + `agastya_session` cookie); `app.use('/api', requireAuth)` once; `requirePermission` on writes (7 permissions; Author = dm:write+graphics:write+publish; Reviewer = dm:status only; Illustrator = graphics:write only; admins all). DM save uses optimistic concurrency (`baseUpdatedAt` -> 409). Publish: `Publisher.ts` -> vendored engine -> xsltproc -> FOP (warm JVM); direct `s1000dtofo` or two-stage `s1000dtojss`+`jsstofo`; HTML via Saxon. Editor: XML -> `XMLTransformer` -> ProseMirror JSON -> serialise back; schema rules = NFA over compiled XSD (`content-models.json`); all actions via `utils/editorCommands.ts`.
- **JSS Publisher**: files = source of truth, SQLite = index/governance. One authz `evaluate()`; every route needs exactly one guard (test enforces). Structural changes via `submitChange()` approval queue. Yjs rooms per document UUID; direct writes must use `commitDirectWrite`. Releases fingerprint the publication; unreleased -> NOT RELEASED watermark. Session = opaque cookie `jss_session`, Argon2id, 7-day.
- **Editor**: XML DOM is the model; MutationObserver undo/redo; grammar compiler + Brzozowski-derivative content-model engine; pdfmake in a Web Worker; mirrored margins, per-DM right-hand pages. Not PM-driven yet (Generate = ticked open DMs).

## 6. Conventions to follow when developing

- Match each project's style; Agastya = TypeScript + comment-heavy "why" notes; JSS Publisher = CommonJS plain JS with `'use strict'`; Editor = TS, no framework.
- Add a route in JSS Publisher -> add its guard + keep `routes-guarded` test green. Add a route in Agastya -> it inherits `requireAuth`; add `requirePermission` on writes.
- Fix shared XSLT/engine bugs in **both** pipelines (`s1000dtofo` and `jsstofo`/`s1000dtojss`) and in both apps if relevant.
- S1000D authoring syntax: `<?page-break?>` (S1000D) / `<pageBreak/>` (JSS); `orient="land"` on table/figure.
- Prefer the narrowest verification that proves the change; report failures with full output.
- Commit only when asked; follow the attribution trailer given by the harness.

### Architecture (read before changing anything)

- **Auth** = JSS modules copied to `backend/src/core/auth/*.js` and mounted via `registerAuthRoutes`. Cookie `agastya_session`, one active session per account, onboarding and

- **Backend services** (`backend/src/services`): `projects` (folders+projects), `csdb` (DM files, identity parse from the 12 KB head, hash-based 409, revisions), `pm`

  watermark), `publisher` (JSS engine: full build, single-DM preview; per-project serialisation), `broadcast` (authenticated /ws, per-project filtering).
- **Engine** = JSS Publisher's newer `engine/pipeline` + Agastya's Publisher.ts flow, in `backend/vendor` (do not edit). Toolchain is Windows (xsltproc+FOP bundled, Java from PATH).
- **Frontend**: routes `/overview /workspace /projects /settings/*` (AppShell) and `/projects/:id/{,editor,explore,publication,validation,release,settings/*}` (ProjectShell, whose
  left sidebar is the project navigation and exposes a portal slot the editor page fills with the DM list + quick preview).
- **Studio embedding**: ONE `App` instance per page (it binds global listeners in its constructor); `lib/studioSession.ts` is the host (open/save through the API with the loaded
  hash, ICN artwork from the project's media, quick preview, open-doc state -> zustand). Patch to `studio/ui/app.ts`: `StudioHost`, `closeAll`, `quickPreview`, `gotoLine`, embedded
  UI trims (no PDF/publication-settings tab, no local Open/Save As/samples), 4 absolute asset URLs. Without a host the Studio is unchanged.
- **Design system**: the platform shares the Studio's CSS tokens (`:root` variables, `html[data-theme]`), so one theme switch covers both; Tailwind preflight is OFF (utilities only);
  platform classes are prefixed `v2-`; `x-*` classes/`--x-*` tokens exist only as a compat layer for the reused Agastya screens (`styles/platform.css`).

- No real-time co-editing: optimistic concurrency only (409, "copy your work, reopen"). No per-DM workflow status UI.
- Viewers can type in the Studio (no read-only mode); saves are refused (403) and a banner says so.

- Studio quick preview can't resolve entity-declared graphics unless they are in the project's csdb/Media (import them with the sidebar upload button).
